# ADR-001: Plugin Boundaries and Permissions

## Status

Accepted

## Context

Приложение требует расширяемость для разных игр, но прямой доступ плагинов к файловой системе создает риски безопасности и нестабильности.

## Decision

- Ввести `Plugin API v1` с ограниченным набором хуков.
- Все filesystem-операции выполняются только через Rust Core.
- Плагин получает capability-based permissions из `manifest.permissions`.
- Несовместимые версии API блокируются на этапе загрузки.

## Consequences

### Positive

- Контролируемая поверхность безопасности.
- Стабильный и версионируемый контракт.
- Прогнозируемая диагностика ошибок.

### Negative

- Часть сложных плагинов сложнее реализовывать.
- Нужно поддерживать эволюцию API и миграции контрактов.

## Alignment with skills

- `plugin-structure`: контракт должен оставаться явным и документированным на уровне manifest/API.
- `tauri-v2`: capability-first модель безопасности соответствует принципу least privilege.
- `best-practices`: ограничение прав плагина снижает риск инъекций и несанкционированного доступа к локальным ресурсам.
