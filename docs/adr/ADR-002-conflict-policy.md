# ADR-002: Conflict Policy v1

## Status

Accepted

## Context

Для MVP нужен простой, объяснимый и детерминированный алгоритм конфликтов без экосистемной сложности уровня LOOT.

## Decision

- Конфликт определяется по совпадению `targetPath`.
- Победитель выбирается по приоритету мода в профиле.
- Результаты сохраняются в `ConflictRecord` и `DeployManifest`.
- Пользователь может менять приоритет вручную.

## Consequences

### Positive

- Простая модель для UX и отладки.
- Предсказуемое поведение деплоя.
- Хорошая база для будущего расширения.

### Negative

- Нет автоматических правил совместимости.
- Ограниченная «умность» для сложных load-order сценариев.

## Alignment with skills

- `solidjs-patterns`: простая и детерминированная модель конфликтов упрощает реактивное состояние UI и снижает вероятность race conditions.
- `performance`: базовый priority-алгоритм дешев по вычислениям и лучше подходит для MVP latency budgets.
- `best-practices`: explainable rules повышают диагностируемость и уменьшают операционные риски.
